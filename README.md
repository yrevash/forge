# Forge-S1

Forge-S1 is a small model that builds CAD parts step by step inside FreeCAD from a structured plan. At every step it reads the plan and the live state of the FreeCAD document, chooses the next command, says which plan item it is working on and where each value of the command comes from, undoes a step that turned out wrong, and says when the part is done.

## What is in the repository

```
forge/
  sandbox.py            run CadQuery programs in an isolated helper process (no network, no writes)
  geometry.py           measure a solid: validity, volume, bounding box, round features
  assembly_geometry.py  measure a multi-part result: per-part sizes, overlaps, touching, groups
  runs.py               run folders: config, command, commit, metrics (runs/<date>-<name>/)
  generators/           part families and structures, generated by code
  system1/              the step vocabulary, the engine that applies steps, the teacher
  freecad/              the headless FreeCAD runtime: commands, snapshot, valid commands, recipes, teacher, sessions
  freecad_multi/        structures of many parts in FreeCAD, on top of freecad/
  freecad_ui/           the same parts built through FreeCAD's buttons and dialogs
  plan/                 strict reader for the plan language
  resolve/              from a read plan to exact parts and a reference build
  plans_data/           the plans the model is trained and tested on
  remote/               record FreeCAD sessions on a Linux machine
  s1/                   the Forge-S1 models: encoding, network, loss, training, evaluation, closed-loop driver
  s1/third/             the released model: it also names where every argument comes from
configs/                training and dataset configs
scripts/                shell scripts for the long FreeCAD jobs
tests/                  the test suite
```

Every folder under `forge/` has a README that says what is in it and how to run it.

## Requirements

- Python 3.12
- [uv](https://docs.astral.sh/uv/)
- FreeCAD 1.1.4 (found by `forge/freecad/locate.py`)

```
uv sync
```

## Run the tests

```
uv run pytest
```

Tests that need FreeCAD or data that is not in the repository skip themselves. One file alone:

```
uv run pytest tests/test_s1_third.py
```

## Load the model and drive one part

The released model is one checkpoint file, `forge-s1.pt`. It is opened as plain data (`forge.s1.train.load_checkpoint`, weights only), and `forge.s1.third.drive.load_any_model` builds the network from it.

To let the model build a part of your own, write a `plan.json` with a name and the plan's items:

```
{"name": "a block with rounded corners",
 "plan": [
  {"kind": "block", "slots": {"length": 320.0, "width": 320.0, "height": 30.0}},
  {"kind": "corner_radius", "slots": {"radius": 20.0}}
 ]}
```

The item kinds and their slots are the step table in `forge/system1/steps.py`. Then:

```
uv run python -m forge.s1.third.probe --checkpoint forge-s1.pt --arguments model plan.json
```

This starts one FreeCAD process without a window. The scripted teacher builds the plan once to get the solid to compare with; then the model builds it from an empty document, choosing every command and every argument itself. The result says whether the part was built right, whether the model said `done`, and how many steps it took. It is written to a run folder under `runs/`.

To drive the model over recorded test parts (this needs the recorded slices under `data/`):

```
uv run python -m forge.s1.third.drive --checkpoint forge-s1.pt --arguments model --seed 0
```

More commands are in `forge/s1/third/README.md`.

## Limits

- Single parts only.
- Features are built on the top face.
- The model follows the order of the plan.
